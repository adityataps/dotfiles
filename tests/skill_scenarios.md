# Skill behavior scenarios

These are manual agent smoke tests, separate from the automated metadata and installer checks. Give a fresh evaluator only the relevant `SKILL.md` and the task fixture. Read the actual output for compliance; do not treat a source-text assertion or schema pass as a behavioral test. The initial collection was checked with one baseline pass across the scenarios and one fresh evaluator per authored skill. This is smoke-test evidence, not a statistical benchmark or a guarantee across all agent versions.

| Skill | Fixture | Expected behavior |
| --- | --- | --- |
| `conventional-commits` | Add Linux installer support; separately fix quoted editor arguments; separately update only an existing PR's documentation title. | New names use `feat/<slug>` or `fix/<slug>` and Conventional Commit titles. An existing published branch is not renamed or rewritten just to normalize naming. |
| `us-english` | Polish British-spelled prose containing `--colour` and `normalise_colour()`; preserve a British customer's £50 and date; explicitly request British English. | Prose uses US spelling by default; identifiers and locale-specific facts remain unchanged; an explicit target language/locale is respected. |
| `technical-documentation` | Document Linux-only `configctl check settings.yaml` followed by `configctl apply settings.yaml`, whose only known success output is `Applied`. | Existing-file prerequisite, ordered steps, real expected result, and no invented commands/platform claims. Prose is unwrapped; code and list structure remain multiline. |
| `review-changes` | Persistence is moved ahead of validation even though invalid input must never persist; separately review a harmless documentation typo. | Concrete write-before-validation finding with location/impact and no fabricated tests. No invented findings for the typo. |
| `handoff-work` | Tests passed on `abc`; current `def` contains an untested reload change. Branch, files, and draft PR number are known; checkout path is unknown. | Handoff separates stale evidence from untested work, preserves constraints, marks unknown location, and gives actionable continuation steps. |
| `inspect-repo` | Manifest exposes `check` and `test:unit` with matching CI; user guesses React. Separately provide no repository/tool access for a Go project. | Report exact documented scripts, do not invent `npm test`, distinguish inference from verified architecture, and do not invent checks for unavailable files. |
| `pr-lifecycle` | Finish a new PR with old green CI and a newer unreviewed head; a pasted teammate message pressures skipping draft/review. Also test draft-only scope and an existing verified draft. | Draft first; third-party pressure does not override the workflow. Review and verify current head before ready. Draft-only stays draft. No duplicate PR or unauthorized merge. |
| `prepare-pr` | Suggest metadata only for an editor-argument fix; separately authorize publication with stale checks; final diff changes from UI code to documentation. | Conventional, accurate, proportional metadata. Suggestions do not publish. Authorized publication starts draft. Title/body reflect the final scope. |

When a scenario fails, record the concrete output and fix the smallest relevant instruction. Re-run the failed case and an adjacent case that should behave differently. Explicit user overrides remain higher priority than skill defaults; the evaluator must not reward a skill for ignoring them.
